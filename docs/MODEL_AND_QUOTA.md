# 生图模型与额度

本文回答两个高频问题：**这个产品用的是什么生图模型**、**订阅了某个套餐能产出几张**。

---

## 1. 生图链路

产线层的图像生成收敛在一个 Provider 抽象里：`engine/stickerpress/imaging/provider.py`。

```
GenerationRequest
   └─ build_provider(kind="auto", sheet=None)
        ├─ SheetFileProvider     # 传了现成大图就跳过生成，model="none"
        └─ AimeImageProvider     # 默认，name="aime-image"
              ├─ 有参考图 → 调用平台 image-generate skill 的 script/image_edit.py
              └─ 无参考图 → 调用 script/image_generator.py
              固定参数：--aspectratio 2:3 --resolution 2k --mimetype image/png
              返回：GenerationResult(model="platform-image-edit")
```

### 1.1 三个不同层次的“模型名”，别混淆

| 名称 | 含义 | 出现位置 |
|---|---|---|
| `aime-image` | **Provider 名**，表示走平台内置图像 skill | `GenerationResult.provider` |
| `platform-image-edit` | **调用方式标签**，表示走的是"图像编辑"入口 | `GenerationResult.model` |
| `image-gen` / `image-gen-2` | **真正的底层模型 ID** | 由平台 skill 内部决定，不在本仓库代码里 |

也就是说，报告里看到的 `platform-image-edit` **不是**底层模型 ID，只是本项目给"走平台图像编辑接口"打的标签。

### 1.2 底层实际模型

平台 image-generate skill 内部的模型选择逻辑：

- 默认 `image-gen`（一代）；
- 传 `--v2` 时用 `image-gen-2`（二代）；
- 环境变量 `AIME_MULTIMODAL_NAME` 可整体覆盖模型名；
- 存在别名映射，例如 `nano-banana-2` → `image-gen`。

本项目当前的 `AimeImageProvider.generate()` **没有传 `--v2`**，因此默认实际跑的是 **`image-gen`**，除非在运行环境里用 `AIME_MULTIMODAL_NAME` 覆盖。

### 1.3 想换模型怎么改

| 目标 | 做法 |
|---|---|
| 换二代模型 | 在 `provider.py` 的 `cmd` 里追加 `--v2`，并在报告中同步真实模型名 |
| 换成任意外部服务 | 新增一个 `StickerProvider` 子类，实现 `available` 和 `generate()`，在 `build_provider()` 注册 |
| 完全不生图 | 用 `SheetFileProvider`，直接喂一张现成六宫格大图；或走 `forge.py assemble` 直接喂 6 张资产 |

无论换成哪个模型，**装配层的几何与合规校验不变**。生图只是插画来源，不能替代印前规则。

### 1.4 装配层不生图

`forge.py` 和 `src/sticker_forge/` **不生成、不分析图像内容、不联网**。它只接收 6 张已经人工复核过的透明资产，做尺寸、间距、刀线、分辨率、自包含性校验，并输出可交付 SVG。这一层与用什么模型无关。

## 2. 能产出几张？

### 2.1 结论先行

**Codex 订阅不是图片额度包。** 「开通 Codex Plus 能出几张照片」这个问题不能直接换算，因为：

1. Codex 是 OpenAI 的**编码 Agent**，其用量额度衡量的是编码任务；
2. OpenAI 官方帮助中心明确说明：ChatGPT 的**文件上传、图像生成、语音**等功能有**各自独立的使用限制**，这些限制不适用于 Codex；
3. 反过来，Codex 的额度也不会转换成图片张数。

所以正确的问法是：**你用哪条图像通道，那条通道当前给你多少配额。**

### 2.2 三种通道各自的算法

| 通道 | 额度口径 | 怎么查 |
|---|---|---|
| ChatGPT App 内建图像 | 按账号套餐的图像生成次数限制，OpenAI 会动态调整 | 触达上限时 App 内会提示；Usage 页可看 |
| OpenAI API / 企业版 | 按 token 计费（图像模型按图像 + 文本 token 计价），没有"张数"上限，只有钱和速率限制 | 官方费率表 + 账单 |
| 本项目默认的平台内置图像能力 | 按所在平台的图像服务配额与速率限制 | 平台侧配额页 / 调用返回的 429 |

### 2.3 本产品每一单消耗多少

一次**顺利**的作业：

| 步骤 | 是否消耗生图额度 |
|---|---|
| 生成六宫格贴纸大图 | ✅ **1 次**图像编辑/生成调用 |
| 色度键抠图 | ❌ 本地 |
| 连通域切分 6 枚 | ❌ 本地 |
| 异形刀版矢量化 | ❌ 本地 |
| A5 SVG 排版与质检 | ❌ 本地 |
| 原图留档、报告、验收 | ❌ 本地 |
| VLM 合规审核 | ⚠️ 消耗**视觉理解**额度，与生图额度通常分开计 |

也就是说：**1 次生图调用 = 1 张 A5 台纸 = 6 枚贴纸。**

### 2.4 换算公式

设图像通道当前可用的成功生图次数为 `N`，实际重试率为 `r`（生成质量不达标、合规拦截后重生成的比例）：

```
可交付 A5 台纸数 ≈ N / (1 + r)
可交付贴纸枚数   ≈ 6 × N / (1 + r)
```

经验值：

| 场景 | 典型 r | N = 50 时的产出 |
|---|---|---|
| 输入照片干净、主体明确 | 0.1 ~ 0.2 | 约 42 ~ 45 张台纸，250 ~ 270 枚 |
| 输入复杂、含人物或潜在 IP | 0.4 ~ 0.8 | 约 28 ~ 36 张台纸，170 ~ 215 枚 |
| 风格反复调整 | 1.0+ | ≤ 25 张台纸 |

导致重试的主要原因：假透明背景、六宫格粘连、主体身份漂移、贴纸上出现文字、合规闸拦截。

### 2.5 怎么把额度用得更省

1. **一次出六枚**：不要一枚一枚生成，六宫格单张大图是当前最省额度的做法（已是默认）。
2. **先预检再生成**：`forge.py preflight` 与 ingest 闸不消耗生图额度，先把不合规的输入挡掉。
3. **复用大图**：`SheetFileProvider` 允许直接喂现成大图重跑排版；调排版、改刀线、换尺寸时**零生图消耗**。
4. **纯排版走装配层**：已有 6 张资产时直接 `forge.py assemble`，完全不碰生图。
5. **失败快速定位**：把 `raw_log` 留档，避免同一个 prompt 问题反复烧额度。

## 3. 报告如实记录

交付报告中的模型字段必须写**实际生效的模型链路**，不能只写 Provider 标签。如果通过环境变量覆盖了模型，请在 `ASSUMPTIONS.md` 或交付报告中注明覆盖值与生效时间。不得伪造模型能力、分辨率或额度结论。
