# 合规策略

实体贴纸一旦印出就会脱离平台流转、可被二次传播且**无法召回**。因此本项目的合规口径比纯线上生图更保守：宁可少做一单，不做一单会出事的。

策略唯一真源：`engine/stickerpress/compliance/policy.yaml`（当前 `policy_version: 2026.09-r3`）。
调整阈值、增删类目、改处置动作**只改这个文件，不改代码**；每次修改必须递增 `policy_version`，版本号会写进审计日志与成品页脚，保证任何一张已印出的贴纸都能回溯到当时生效的策略。

前端策略副本由 `python3 engine/tools/sync_policy.py` 从 YAML 同步到 `console/src/lib/compliance/policy.json`，不要手改副本。

---

## 1. 三道闸

| 闸 | 时机 | 检查对象 | VLM 复核 |
|---|---|---|---|
| **ingest** 入料 | 用户上传后、生成前 | 原始照片 | ✅ |
| **generation** 生成 | 构造提示词时 | 主体描述 / 提示词 | ❌（规则过滤） |
| **egress** 出料 | 生成后、排版前 | 六宫格大图与每一枚贴纸 | ✅ |

三道闸可独立启停，便于灰度与压测。

### fail-mode

`fail_mode: review`。VLM 不可用、超时或解析失败时**降级转人工**，不静默放行。设成 `pass` 属于激进配置，仅用于压测环境。

---

## 2. 处置动作

| action | 含义 |
|---|---|
| `block` | 直接拦截，不进入生成，返回明确拒绝理由 |
| `review` | 转人工复核，不阻断下游流程但**不允许下单印刷** |
| `mitigate` | 自动处置后放行（擦除 / 脱敏 / 降级），并记录处置手段 |
| `pass` | 放行 |

严重度 `S0`（法律红线）→ `S3`（体验瑕疵）。

---

## 3. 风险类目总表

### A. 肖像与主体

| 码 | 类目 | 严重度 | 处置 | 命中闸 |
|---|---|---|---|---|
| A1 | 未成年人肖像 | S0 | block | ingest, egress |
| A2 | 非本人／多人肖像 | S1 | review | ingest |
| A3 | 公众人物／名人 | S0 | block | ingest, egress |

A1 在 C 端自助链路一律拦截：未成年人肖像商品化需监护人单独同意，产品侧不具备核验能力；需走 B 端定制通道，上传监护人授权书后人工开单。

A2 的判定口径：只有画面中出现**真实人类面孔**才命中。宠物、玩偶、卡通形象、雕塑、无脸背影**不命中**。单人自拍也命中（无法确认是否本人），但严重度低于多人合影。

### B. 知识产权

| 码 | 类目 | 严重度 | 处置 |
|---|---|---|---|
| B1 | 知名 IP 角色 | S0 | block |
| B2 | 商标／品牌 Logo | S1 | mitigate |
| B3 | 他人美术作品复制 | S2 | review |

### C. 内容安全

| 码 | 类目 | 严重度 | 处置 |
|---|---|---|---|
| C1 | 色情低俗 | S0 | block |
| C2 | 血腥暴力 | S0 | block |
| C3 | 政治敏感／国家象征 | S0 | block |
| C4 | 歧视／仇恨符号 | S0 | block |
| C5 | 毒品／武器／赌博 | S0 | block |
| C6 | 自残／极端行为 | S0 | block |

### D. 隐私与识别信息

| 码 | 类目 | 严重度 | 处置 |
|---|---|---|---|
| D1 | 证件／银行卡／车牌 | S0 | block |
| D2 | 二维码／条码 | S1 | block |
| D3 | EXIF 地理位置／设备信息 | S2 | mitigate |

D2 拦截而非脱敏：印在实体贴纸上的可机读码可能被扫描后指向任意内容，风险不可控。

D3 自动处置：原图**字节级副本保留原样**（交付要求），但生成链路与交付报告中不带出地理位置和设备信息。

### E. 商业与表述

| 码 | 类目 | 严重度 | 处置 |
|---|---|---|---|
| E1 | 贴纸上出现文字 | S2 | review |
| E2 | 货币图样 | S0 | block |
| E3 | 功效／医疗宣称 | S1 | block |

E1 的口径经过一次修订（`2026.09-r2`）：装饰性拟声词（如 `Zzz`、`!`）不应一律判违规，但**任何可读文字都必须人工确认拼写与含义**——生成模型的错字率在实体印刷场景不可接受。

## 4. 权利边界

**生成贴纸不自动取得商业使用权。** 处理照片前，优先核对：

1. 用户是否拥有照片本身的著作权；
2. 画面中可识别人物是否授权商用；
3. 私有场地、受保护素材是否授权商用。

`rights.json` 缺省即拒绝，`unknown` / `n/a` / `待确认` 不算授权。可识别人物 → `portrait_release` 必答；第三方 IP → `ip_license` 必答。详见 [`ARTWORK_CONTRACT.md`](ARTWORK_CONTRACT.md) 第 4 节。

### 选材倾向

| 优先选材 | 保守排除 |
|---|---|
| 用户随身物 | 现代受保护建筑的可识别主体 |
| 自然景物、植物 | 受版权保护的艺术装置 |
| 食物 | 海报、他人摄影作品 |
| 通用旅行物 | 景区吉祥物、文创商品设计 |
| 无文字的纪念性物件 | 盲盒 / 手办形象 |

授权不明时，改为自然元素、普通物件或抽象背景。

**不得因"恰好六枚"的数量要求而用高风险元素凑数。**

---

## 5. 不可替代的东西

- **不用免责声明代替处理**。任一阶段发现高风险元素，替换或剔除，不是加一行"如有侵权请联系"。
- **不伪造合规结论**。交付报告必须说明"已检查到的风险与处理方式"，不承诺绝对法律结论；需要法定授权的内容标记为"需用户确认"。
- **自动化不替代人工复检**。`forge.py verify` 只验几何，内容合规必须有人看过成品。
- **本项目不替代律师**。可以识别并降低常见风险，不能替代权利审查。

## 6. 红队回归

```bash
python3 engine/tools/make_redteam_samples.py   # 生成对抗样本
python3 engine/tools/redteam_suite.py          # 跑回归
```

样本在 `engine/samples/redteam/`。**每次修改 `policy.yaml` 后必须跑红队回归**——历史上出现过仿证件样本被误判 `pass` 的严重漏检（原因是 VLM 输出被包在工具结果外壳里、解析器未解包，见 `CHANGELOG.md`）。审核链路的 bug 不会自己暴露，只能靠对抗样本打出来。
