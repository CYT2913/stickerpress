# 视觉资产交付契约

装配层（`forge.py` / `src/sticker_forge/`）**不生成也不分析图像内容**。它把 6 张已经通过人工复核的插画资产装配成可交付的 A5 台纸。本文规定视觉 Agent（或设计师）必须交给装配层什么。

不满足本契约的资产，装配层要么直接报错，要么产出印出来才发现问题的版——两种都算交付失败。

---

## 1. 交付清单

一次装配需要：

| 项 | 要求 |
|---|---|
| 6 张贴纸资产 | 正好 6 张，见第 2 节 |
| 1 张来源照片 | 用户原图，装配层只做字节级复制 |
| 1 份 `rights.json` | 权利声明，见第 4 节 |

---

## 2. 资产文件要求

| 项目 | 要求 |
|---|---|
| 数量 | **正好 6 张**。多一张少一张都会被 `assemble` 拒绝 |
| 格式 | `.png` / `.jpg` / `.jpeg` / `.webp`；**推荐 PNG** |
| 透明 | 必须是**真透明 alpha**，不是棋盘格贴图，也不是白底 |
| 最低分辨率 | 装配后有效 dpi 必须 ≥ 300，目标 400 dpi |
| 建议像素 | 单枚建议 ≥ 1000 × 1000 px（对应 62 mm @ 400 dpi 约 977 px） |
| 目录 | 全部放在**一个独立目录**下，目录里不要放原图或其他图片 |
| 排序 | 装配层按**文件名字典序**读取并依次放入 6 个格位 |

### 命名

推荐 `sticker_01.png` … `sticker_06.png`。因为按字典序排，`sticker_1` 到 `sticker_10` 这种不补零的命名会乱序。

> ⚠️ 常见坑：把来源照片和 6 张贴纸放在同一个目录，装配层会收集到 7 个文件并报错"需要正好 6 张"。贴纸单独放一个 `art/` 目录。

### 构图

- 主体居中，四周留少量透明边（约 2–5% 边长），避免刀线贴主体边缘；
- 单枚长宽比不要太极端，接近正方或 3:4 最容易在 2×3 格位里排得好看；
- 不要在资产里自带白边描边以外的背景块；如需白色描边，应作为主体的一部分带 alpha 输出。

---

## 3. 透明背景怎么做

直接要求模型输出"透明背景"通常得到的是**画出来的棋盘格**，没有真 alpha。本项目采用的做法：

1. 让模型在**纯品红 `#FF00FF`** 背景上作画；
2. 后处理做色度键，只移除与画面边缘**连通**的品红像素——这样主体内部的品红细节不会被误穿孔；
3. 边缘做去色溢（decontaminate），避免品红镶边；
4. 再按 alpha 连通域切分六枚。

产线层 `engine/stickerpress/imaging/chroma.py` 和 `segment.py` 已实现。若用其他工具产出资产，也必须保证：**没有残留品红边、没有半透明脏边、没有主体内部误穿孔**。

---

## 4. 权利声明 `rights.json`

生成模板：

```bash
python3 forge.py rights-template > rights.json
```

规则：

- **缺省即拒绝**。字段缺失、留空一律视为未授权；
- `unknown` / `n/a` / `待确认` / `不确定` 等**不算授权**；
- 画面含可识别人物时，`portrait_release` 为**必答**；
- 画面含第三方 IP 元素时，`ip_license` 为**必答**；
- 声明人（姓名/联系方式）必填，不能匿名声明。

未通过时 `assemble` 以退出码 2 结束，只产出说明性报告，**不产出任何印刷文件**。这是设计上的硬拦截，不要绕过。

---

## 5. 选材与合规

选材前先读 [`COMPLIANCE.md`](COMPLIANCE.md)。要点：

**优先选**：用户随身物、自然景物、食物、植物、通用旅行物、无文字的纪念物。

**禁止直接复现**：商标、品牌名、Logo、产品包装、版权角色、盲盒/手办形象、景区吉祥物、文创商品设计、票券二维码、车牌、联系方式及其他隐私标识。

**保守排除**：现代受保护建筑的可识别主体、受版权保护的艺术装置/海报/摄影作品。授权不明时改用自然元素、普通物件或抽象背景。

**人物**：无明确授权时不保留可识别肖像，可改为背影、剪影或不具识别性的通用人物。

**不得为了凑满六枚而引入高风险元素**（`AGENTS.md` 0.6）。照片里凑不出 6 个合规主体时，用照片的色彩、天气、纹理或通用旅行物补足。

---

## 6. 交付前自检

在把资产交给装配层之前，逐项确认：

- [ ] 正好 6 个文件，放在独立目录，命名补零
- [ ] 每张都有真 alpha，放到深色背景上看无品红残边、无脏边
- [ ] 每张主体完整，无被误抠掉的内部区域
- [ ] 每张像素量足够（≥ 1000 px 短边）
- [ ] 六枚风格统一（线条粗细、描边、配色体系一致）
- [ ] 六枚彼此有辨识度，不是同一主体的六个角度
- [ ] 无品牌 / Logo / 版权角色 / 二维码 / 车牌 / 证件信息
- [ ] 无未授权可识别人物
- [ ] 贴纸上没有出现意料之外的文字或错字
- [ ] `rights.json` 已按实填写，无 `unknown`

装配完成后再跑一次独立验收：

```bash
python3 forge.py verify outputs/<order>/a5-six-stickers.svg
```

自动验收通过 ≠ 合规通过。内容合规必须人工看过成品才算数。

---

## 7. 装配层会替你检查的 / 不会替你检查的

| 装配层会检查 | 装配层不会检查 |
|---|---|
| 资产数量正好 6 | 画得好不好看 |
| 文件能否解析、宽高 | 是否真透明（只看有无 alpha 通道无法判断脏边） |
| 有效 dpi ≥ 300 | 风格是否统一 |
| 单枚尺寸 20–62 mm | 内容是否合规 |
| 刀线净距 ≥ 8 mm | 是否含未授权肖像 / IP |
| 安全边距 ≥ 10 mm | 权利声明内容是否属实 |
| SVG 自包含 | 印厂模板是否匹配 |

右列全部是**人的责任**，不要指望自动化兜住。
